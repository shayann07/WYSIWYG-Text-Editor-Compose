# Existing SkShaper glyph/cluster capability and layout parity

The installed Skiko 0.150.1 paragraph wrapper has no glyph-run visitor, but its existing `Shaper` / `RunHandler` API supplies glyph IDs, positions, source clusters, bidi levels and actual run fonts. This is a distinct concrete capability from the rejected naive invisible-character PDF layers. No replacement shaper, native binding or additional dependency was created.

`GlyphClusterProbe.kt` executes that API against the pinned Noto Nastaliq Urdu font and the actual Compose paragraph layout. Four Urdu, diacritic, mixed-script and joining specimens at widths 180/420 yield eight samples. It compares three existing wrapper factories, each with integer/subpixel metrics: 48 actual shaping trials. Callback glyph/position/cluster counts and paragraph-global UTF-16 ranges must be valid. Font clones are read inside the callback and closed. The width threshold is declared at <=0.25pt.

Compose's visible line width omits trailing whitespace while the callback's advance includes it. The comparison therefore uses the full logical-unit bounding extent, including trailing spaces, on both sides; the original visible-width diagnostics are retained. Text and break expectations are not normalized or modified to declare success.

Result: **glyph-cluster capability exists, but no tested configuration is a complete layout substitute**. Subpixel metrics match the pure Urdu/marks/joining cases. In the narrow mixed-script specimen, the shaper-driven wrapper breaks the second line at offset 27 while Compose breaks at 26, with a material width mismatch. Default/shape-then-wrap differ more substantially. A callback from an independently reshaped paragraph is not the actual Compose paragraph's glyph stream.

The integrated desktop verifier runs the experiment against its fresh isolated build. Evidence records all source units, line ranges, advances, glyphs, clusters, positions, fonts and configuration verdicts. No PDF is generated. A future route needs actual paragraph glyph access or a separately qualified mapping with ink/cluster geometry parity before semantic PDF testing. GP0 remains open.

Primary API sources: [RunHandler documentation](https://jetbrains.github.io/skiko/skiko/org.jetbrains.skia.shaper/-run-handler/index.html), [RunHandler source](https://github.com/JetBrains/skiko/blob/master/skiko/src/commonMain/kotlin/org/jetbrains/skia/shaper/RunHandler.kt), [RunInfo source](https://github.com/JetBrains/skiko/blob/master/skiko/src/commonMain/kotlin/org/jetbrains/skia/shaper/RunInfo.kt). These live sources are leads; installed signatures and actual callback observations are the version-specific evidence. The installed adapter reports paragraph-global cluster offsets, so the probe checks those directly instead of adding a guessed run offset.
