# Bounded tooling checkpoint and expired-offline recovery

The private SQLite authority now has an explicit checkpoint/epoch boundary. This resolves a feasibility gap in its prior full-log replay experiment; it does not select a production persistence schema, garbage collector or collaboration algorithm.

Compaction writes a checksum- and source/runtime-bound checkpoint and removes the accepted event rows in one WAL/FULL transaction. The accepted frontier and canonical sequence remain distinct and monotonic. Semantic inverses, group metadata, attribute ownership and deleted preimages are retained. Obsolete transport packets and idempotency receipts can retire because a new epoch fences every old request namespace before admission. Repeating compaction with no new rows returns AlreadyCompacted without rotating again. New requests must carry the current epoch, an epoch-specific identity and a supported captured basis; guessed future bases refuse.

An offline client's old request receives an explicit recovery outcome with its original intent and no acknowledgement. Relabeling that old identity under a fresh epoch is refused. The client must preserve old work, resynchronize, and admit any eventual recovery as a new explicit action. The experiment does not silently rewrite or auto-import its old outbox.

Open gestures defer compaction. A trusted test-service retirement control retires one producer and closes only that producer's groups while preserving its accepted prefix. Author permissions remain separate: another device of the same author keeps its open gesture and pins compaction until its own close. Group append/close, local Undo/Redo, redo abandonment and own-history discard are producer-scoped. A device cannot consume or discard another device's local history; explicit shared-resource release still waits for all relevant histories. Actual permission revocation remains the separate role control. The fixture identities are trusted stubs, not authenticated devices or a production allocation scheme.

Producer retirement is a server admission decision, **not a native IME fence**. The actual JVM case preserves its complete local frame, raw attributes, unsent intent and candidate in a separate SQLite recovery record before abort/adoption. A snapshot cannot change the composing replica. Abort alone cannot release it. Only an explicitly labeled synthetic fence permits the later explicit projection replacement. The old recovery record remains intact; late callbacks refuse, and fresh-epoch editing works. Production recovery UI, authentication, real native fence/storage atomicity and lease-expiry scheduling remain unimplemented.

The tooling checkpoint uses the existing Node V8 serializer to preserve Maps, Sets and property presence. A concrete JSON control loses `expectedOwner: undefined` from a Redo inverse, then incorrectly overwrites a later peer relocation. The V8 checkpoint retains the guard and refuses that Redo. Semantic hashes also distinguish absent from present-but-undefined fields. Source/runtime/version/checksum mismatches refuse while retaining the database. This runtime-specific representation is deliberately **not** a portable production format or an S0 schema decision.

`compaction-recovery.mjs` executes nine named checks through actual separate service processes, including exits before and after checkpoint COMMIT, grouped selective history, deleted attribution, ownership guards, two producers of one author, producer retirement, integrity/compatibility corruption controls, and the actual JVM offline-frame case. Process exits and data-corruption/serialization controls are labeled separately from implementation-source mutants. The integrated verifier supplies a fresh isolated build and records commands, exit codes, source/runtime identities, every stage artifact and owned JVM termination. Direct focused runs take `--build=<build> --output=<new-directory>`.

The strengthened resynchronization specimen contains peer B/I formatting, a paragraph split and a literal soft newline. `native-paragraph-projection.mjs` validates the canonical snapshot and compiles supported paragraph units without normalizing all newlines or clearing attributes. One actual owner transaction preserves exact raw units/kinds/styles/paragraph flags and leaves local snapshot history untouched. A reproduced earlier adapter normalized an italic peer unit to plain; the failing assertion and original runner are retained. Unsupported lists/tables, unknown attributes/paragraph properties and invalid canonical identities refuse before owner editing. This bounded paragraph projection is not a general rich-flow import. The four malformed UTXT-151–154 fixtures also pass through the compiler and actual JVM, with alternating B/I flags. Full replacement is restricted to the explicit resync experiment; normal typed updates remain granular.

The checkpoint has a 32 MiB serialized payload limit. This is not a heap, throughput or document-capacity qualification. Semantic inverse/resource/offline-replica leases are retained conservatively; **no semantic retention garbage collection is performed**. Total retained semantic state can still grow. Active-client compaction policy, power loss, concurrent server writers, scalable replay/storage, portable codec/migrations, producer allocation/authentication and native recovery remain C0/S0 work. No user `.astra` file is changed or migrated.

The later [portable representation trial](PORTABLE-CHECKPOINT.md) adds an optional source-bound codec alongside the default V8 lane. Actual Python decode/re-encode, retained ownership guards, raw UTF-16 and the same process-fault/JVM cases are tested. This narrows the runtime-specific payload risk; an accepted production codec and migrations remain unresolved. Neither lane performs semantic retention garbage collection.
