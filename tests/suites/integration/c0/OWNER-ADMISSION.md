# Actual-owner composition and remote-admission experiment

`composition-admission.mjs` runs the real prototype EditorEngine in its own JVM through the local JSON-line probe. It combines that owner with the private ordered structural authority/readonly replica model. It is a synthetic protocol experiment; no OS IME or native retirement is qualified by it.

The native owner starts an attributed composing island in a header specimen. Remote changes arrive before, inside and after the island. Accepted local prefix effects are sent to the ordered authority immediately, while unaccepted candidate content is never broadcast. The readonly accepted-state replica buffers remote/echo packets, and the actual owner's text, attributes and coordinate basis remain unchanged while composing. A caret command waits for the ordinary terminal boundary rather than redirecting the candidate.

At a verified synthetic terminal callback, the queue drains. An external semantic-ID mapping compiles targeted raw edits into **one actual owner transaction** and maps the logical caret by surviving identities. Unrelated internal unit IDs remain intact. Remote changes do not clear or append local root-snapshot history. A one-way internal probe history port routes user Undo/Redo to selective authored group inverses; it never restores an old local root over peer contributions.

The test verifies a gesture with partial acceptance followed by remaining-candidate commit, then exact group Undo/Redo retaining all three peer contributions and their attributes. Stamped late callbacks and closed gesture appends reject. A second case explicitly aborts the remaining candidate: the accepted prefix survives, but an engine abort/frame alone cannot release remote work. The model requires an explicit qualified retirement boundary. That boundary is deliberately labeled **SYNTHETIC_FENCE_FIXTURE_NOT_OS_QUALIFICATION**; the real adapter's fence remains a gate.

The internal `CanonicalProbeEdit` boundary is experimental. It rejects composing/busy/stale bases, applies raw units/attributes atomically and returns a receipt from the commit point, before observer callbacks. Kernel regressions include invalid later edits, hidden constituent attribution, preserved local history, deferred history requests and later observer failures. The same commit receipt also fixes recovered-draft success being incorrectly relabeled by a later independent observer edit.

Canonical admission now requires the captured semantic revision **and the complete ordered committed-unit identity vector**. A real engine baseline showed that replacing `ک` with `ک` allocates a new local ID while the semantic revision stays fixed; the old revision-only request could then edit that different unit. `CanonicalProbeBasis` rejects this identity-only drift without changing semantic revision rules or invalidating caret-only changes. This full-vector check is bounded prototype evidence, not the final persistent index or scalable public API.

The private JSON-line endpoint also binds each canonical request to a fresh process-incarnation nonce. A new endpoint can allocate the same local IDs/revision; a packet captured from the old endpoint must still refuse. Committed IDs have a decimal-string field consumed by this admission path; numeric/missing/overflowing encodings reject. Legacy numeric fields remain for existing probe diagnostics, so this does not qualify every identity transport path or full-range ID allocation. `canonicalBasis(frame)` copies metadata from the frame that supplied the target; callers must not silently refresh an old request's basis. Existing epoch checks still precede admission, and composition still defers without mutation.

`canonical-identity.mjs` executes five checks across two actual JVM endpoints: cross-incarnation reuse, same-text identity drift, caret independence/local-history preservation, malformed identity basis refusal, and synthetic composition/abort/stale-epoch behavior. Protocol corruption cases are not implementation mutants. Both JVMs must close. Global/durable canonical identity allocation, engine/codec import retention and rich-flow mapping remain S0 work; no public schema or native fence is selected.

The later [typed identity pairing trial](TYPED-IDENTITY.md) separates text-unit IDs from paragraph-boundary provenance and compiles selective targets against that exact owner basis. Actual JVM cases cover repeated Urdu, interleaved peer units, external Undo, provisional isolation and malformed U0 units. It is a runtime single-flow pairing experiment; durable imports, identity-aware moves and resynchronization/fence policy remain unresolved.

These are not stable library APIs, persistent IDs, a production typed wire format, a collaboration UI, durable outbox/group allocation or a native focus/restart proof. The mapping is in memory; production Kotlin owner/schema/identity design and native qualification remain open. Run the integrated verifier for fresh classes and command/exit receipts. Direct runs require `--build=<fresh-build> --output=<new-directory>`; add `--terminal=abort` for the abort/fence case. The owned JVM closes after each case.

`--queue=overflow` forces the readonly replica's queue limit to two entries. Further peer/echo packets signal resynchronization without modifying the composing owner. An adequate explicit authority snapshot is refused until the verified synthetic terminal boundary; older-frontier snapshots also refuse. After that boundary, resynchronization and the existing targeted owner reconciliation preserve accepted local text, identity mapping, peer attributes and selective gesture Undo/Redo. This is a bounded protocol check; native restart, production queue latency, authenticated snapshots and durable recovery remain unqualified.
