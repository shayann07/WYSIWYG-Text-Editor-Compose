# Bounded SQLite / process-restart experiment

`durable-authority.mjs` wraps the existing private ordered authority with SQLite's WAL and `synchronous=FULL`. It logs accepted typed events, exact receipts and a hash of semantic state, authored history, groups, retained identities and ownership maps. Every reopen replays those events through the same model and checks both receipts and state hashes. This is deliberately full replay over a small fixture, with no production storage/schema/algorithm selection.

`durable-replay.mjs` runs an actual JVM owner plus separate short-lived Node service processes. Each service request has an idempotency identity. Two intentional **process-fault controls**, distinct from implementation-source mutants, exit after the SQL insert but before COMMIT, or after COMMIT but before writing the acknowledgement. The first transaction rolls back on reopen. The second survives; retransmission returns its durable receipt without another effect or history group. The same lost-ack check covers Undo, whose duplicate must not consume a second history entry. Authored two-part groups and their selective Undo/Redo survive separate process restarts. Role revocation is replayed and checked before duplicate receipt lookup; rejected work stays in the local recovery outbox.

The JVM's accepted transaction contains exact Urdu raw units and bold/italic attribution. A separate local SQLite transaction stores its projection and pending outbox state together. Reopening that database preserves the whole recorded frame. “Prepared recovery intent”, “local durable / pending sync” and “acknowledged” are distinct states. The intent is recorded before the experimental canonical command is sent to the owner. A prepared intent whose owner outcome was never confirmed requires explicit recovery admission; it is not silently labeled saved or synchronized.

All four existing malformed UTXT-151–154 fixtures also cross the SQLite commit/lost-ack/replay and actual JVM JSON path. Raw numeric units, string code units and attribution must agree exactly, including isolated surrogates; scalar-count metadata is not substituted for raw UTF-16 fidelity.

Run through the integrated verifier, which supplies the same fresh isolated build used by the Urdu and desktop checks. A direct focused run takes `--build=<build> --output=<new-directory>`. The report includes actual child commands, exit codes 83/84 for the intentional faults, SQLite version, source/build hashes and owned JVM termination. SQLite databases and logs are disposable evidence inside that directory; no user document or OS configuration is changed.

This does **not** prove native-callback/storage atomicity, an app autosave feature, JVM-crash recovery of production identities, filesystem/power-loss durability, real authentication, multi-writer service concurrency, compaction or scalable replay. Stable IDs belong to the existing experimental model; the prototype's local IDs and codec mapping remain an S0 issue. The real IME adapter still needs a qualified durable publication/recovery protocol. No acknowledgement is inferred merely from enqueueing a request. C0 remains open.

The later [compaction experiment](COMPACTION.md) preserves field presence in tooling checkpoints and tests old-epoch recovery separately. It adds no production persistence guarantee to this original replay scope.

The later [writer contention trial](WRITER-CONTENTION.md) adds typed non-acknowledging Busy admission, actual separate-process transaction barriers, rollback/retry/duplicate and compactor-epoch cases in both codec lanes. It qualifies those bounded initialized-database cases, not general multi-server throughput, first-time provisioning races or native storage atomicity.
