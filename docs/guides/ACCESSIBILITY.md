# Desktop editable-accessibility slice (F39, M1)

The mounted AWT input surface exposes `AccessibleEditableText` in addition to text, selection, style and page-aware geometry reads. Plain text replacement/insertion/deletion, selection and bold/italic attributes enter the existing EditorEngine owner. There is no second text component or independent accessibility history.

Text indices are half-open UTF-16 ranges. Protocol text replacements preserve exactly the requested units, including edits inside a surrogate pair or combining sequence; keyboard grapheme commands retain their existing snapping policy. Opaque LF inserted through this text API remains a soft text LF. It does not synthesize Enter or a structural paragraph command. Existing structure/attributes outside the target remain intact.

Requests from a bridge thread are marshalled to the owning EDT. The document basis is captured before queueing; a changed basis throws `AccessibilityBaseChanged` rather than editing a later position. Caret-only changes do not redirect an explicit text target. Composition-time commands retain captured engine targets through settlement; a vanished provisional target rejects. Retired or input-paused surfaces cannot accept accessibility writes.

Bold and italic can be patched together as one reducer publication and Undo step. Formatting uses the core's existing grapheme-format policy. Unsupported attribute keys reject the entire request. Character attribute reads expose stored inline/paragraph flags plus the requested presentation family and logical size. These reads marshal to the owner so the profile and visible frame agree. Pinned candidate family names are read from the verified font resource; the generic system request is SansSerif. This is not a physical fallback-face report. Switching the shell profile emits typed attribute notifications for contiguous equal-style runs after updating presentation, preserving text, structure, selection, composition and history. Selecting the same loaded profile emits no redundant notification; an empty document has no character span to notify. Text and attribute notifications carry standard `AccessibleTextSequence` / `AccessibleAttributeSequence` payloads after coherent publication; caret/selection notifications follow the same frame.

Validation: the integrated verifier executes mounted API text/style/structure/raw-unit cases and synthetic composition/queued-history cases. A separate real worker-thread test checks EDT handoff, a deterministically queued stale request and retired-surface admission. Paged-host checks exercise the same geometry through AccessibleText. The queued bold/italic regression begins from plain attributes so it must perform a real mutation before Undo.

Run `python desktop-prototype/verify.py` for fresh integrated evidence. Focused background-bridge checks use `editor.MainKt --accessibility-thread-check --host-result=<new-result-path>` on a fresh verified classpath.

Real OS screen-reader/braille editing, system clipboard interoperability, external bridge timing/provenance and other target platforms remain unqualified. Cut/paste routes use the existing system clipboard and are not invoked by the automated tests. This slice does not qualify the full F39 capability. API reference: [Java 23 AccessibleEditableText](https://docs.oracle.com/en/java/javase/23/docs/api/java.desktop/javax/accessibility/AccessibleEditableText.html).

The later [native JAB spike](../../tests/suites/accessibility/jab/README.md) now checks actual DLL traversal/read/write/selection, B/I attributes, paged device-coordinate forwarding, raw malformed units and attributed Undo/Redo on this Windows/JDK target. It exposed and fixed the missing Accessible marker: the editor is reachable through the standard window tree, not only a direct reference. Bridge activation is process-local to the owned offscreen fixture; both native/client JVMs close. This is native AT protocol evidence, not screen-reader speech or native keyboard/IME qualification. Requested family/size is now checked through native JAB for all four profiles, including styled paragraph-break attributes; physical fallback runs and upstream unstamped timing remain open.
