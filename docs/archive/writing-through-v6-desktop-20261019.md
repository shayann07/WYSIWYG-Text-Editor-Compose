Selection targeting remains normalized half-open; ending at the next paragraph start excludes it. Each command is one Undoable transaction.

**Links:** distinct IDs identify runs even if their URI strings match. Selected link edits expand to displayed grapheme boundaries under existing formatting rules, preserving other attributes. At a collapsed caret, automatic typing inherits a link only when both adjacent units have the same ID; exterior edges type outside. Whitespace/Enter leave link continuation. **Images:** one tagged U+FFFC IMAGE unit occupies a standalone block. It is an atomic selection/replacement object, not editable text. Text insertion at an unselected image seam refuses: move to the neighboring paragraph. Explicit image insertion splits text and creates an editable landing paragraph; inside a list item all resulting blocks retain that item membership and only its first paragraph has a marker. No cropping, text wrapping, SVG, remote download or image editing is provided.

## Scope and limits

This is a local desktop writing harness, not the complete application/library release. New `.astra` v5 files preserve UTF-16, bold/italic, starting/paragraph typing styles, hard/soft breaks, and persistent paragraph direction/alignment. Versions 1–4 remain readable with Auto/Start paragraph defaults. It does not promise persistent unit identities or production-format compatibility. The prototype file limit is 100,000 UTF-16 units. Save is explicit. Automatic local recovery copies protect the last completed committed-content checkpoint; they do not save into your named document or provide power-loss durability. Opening makes a new window. Font/page presentation is a launch/window choice rather than file metadata.

Pagination is experimental. Qualified semantic PDF/printing, full screen-reader behavior, expert Urdu typography review and Android/iOS/Web product support remain open. Real keyboard evidence and synthetic composition/offscreen evidence are recorded separately in `docs/reports/overnight-progress.md`. Japanese activation diagnosis is outside this bounded writing milestone.

Recovery diagnostics may contain the test/document input you inspect or export; keep those files local as appropriate. Existing diagnostic filenames are not overwritten: choose an unused name. Hover a truncated title/status to read its full path/message.

## Automatic local crash recovery

Launch normally with `write-urdu.cmd` (blank) or `write-urdu.cmd --sample`. Committed text, supported bold/italic/start/paragraph styles and hard/soft breaks are checkpointed into `%LOCALAPPDATA%\AstraEditorPrototype\recovery` (home-folder fallback if LOCALAPPDATA is absent), separately for each window. The footer says **Recovery copy HH:mm:ss** after a successful publication. **Recovery pending** means newer accepted edits are not protected yet. A failure stays visible with a detailed tooltip and retries on the next tick.

Scheduling ticks every two seconds and uses one active write plus one coalesced newest snapshot per window. This is **two seconds plus UI scheduling and disk time**, not a hard maximum-loss guarantee. Only the last completed copy is protected; later keystrokes may be lost. Disk-full/permission failures can extend this window indefinitely until a write succeeds. An older completion never replaces a newer successful copy. The previous valid checkpoint remains as a fallback while the next is written and atomically published. Corrupt/truncated latest records produce a visible fallback warning. An unfinished temporary record is never restored as committed content.

After an abnormal exit, launch with the same Windows user. **Local recovery copies** appears if inactive copies exist; you can also open **Recovery Copies…** while writing. Each item shows its document name and snapshot time. Select it and choose **Restore Copy**. This makes a **separate unsaved document**, with an asterisk and a Save As prompt. The original file is never automatically opened for writing, even if missing or externally changed. Save the recovered content to a separate `.astra` file. Ordinary Save and Save As keep their existing meaning and dirty-state rules. If Save completes while later edits exist, those later edits stay dirty and their recovery copy remains.

Successful restore keeps the source copy until **Discard Copy…** explicitly confirms its removal (including its fallback). **Later — keep copies** dismisses the chooser without deleting anything. A failed restore keeps its files. Running windows' copies are hidden from the recovery list; locked copies from another process are not claimed as abandoned. Normal clean close, successful Save-and-Close, or an explicit discard-close retires only that window's own automatic copy. Cancel does not retire it. No unrelated unresolved copy is automatically evicted. Small per-session lock/discard markers can remain in the recovery folder; this prototype has no capacity/retention policy.

**Committed content only:** provisional IME candidates are not checkpointed. Already accepted partial commits are eligible. Existing retained composition drafts and quarantined/unverified callbacks remain **memory-only** and separate from these files. Their current close, export and snapshot-discard protections remain; a process crash can lose them. Never treat their callback text as a committed recovery document. Export them explicitly before closing when needed.

This is a private versioned prototype envelope around the existing `.astra` codec, not a production document schema. Process-kill tests do not qualify power-loss/directory durability. Existing 100,000 UTF-16-unit codec limits apply. Restore does not restore Undo history, selection, font/page preferences or native composition state; it restores the supported committed document payload. Keep the recovery directory private: it contains your text and original file path metadata.

For a disposable isolated trial, pass `"--recovery-dir=D:\Your Test Folder\recovery"` after the launcher. Use the **same directory on relaunch**. To verify automatically, run `python desktop-prototype/verify.py --local-recovery-milestone` from the repository root. This uses a fresh isolated build for current writing/quarantine/recovery/U0 checks and actual owned child-process kills; it does not rerun collaboration/schema/PDF experiments.

## Find and Replace — exact literal Unicode

Ctrl+F opens Find; Ctrl+H opens Find and Replace. Type/paste a literal query into **Find**. **Enter / Shift+Enter** navigate next/previous in logical document order, wrapping at the ends; the counter shows current / total. Previous/Next buttons do the same. Matches reveal themselves by scrolling in continuous and experimental pages. Escape closes the panel and returns focus to the document. Close retains the ordinary document selection at a safe selected match; search highlight colors are transient and never stored as formatting.

The first version is **case-sensitive, exact UTF-16/Unicode literal matching**, with no regex, fuzzy matching, normalization, diacritic removal or Urdu/Arabic letter equivalence. For example ک and ك, ی and ي, marked/unmarked text and differently encoded combining sequences remain distinct. Matches are non-overlapping: `aa` in `aaaaa` gives positions 0 and 2. It searches the prototype's supported flat body within each **hard paragraph**; hard paragraph separators are not searchable text and cross-hard-paragraph matches/replacements are not supported. This does not flatten hard/soft distinctions.

**Ctrl+Enter inserts a literal soft line break in either field**; Enter/Shift+Enter remain navigation keys. A query containing LF matches existing soft line breaks within a paragraph. Replacement LF creates soft line breaks only; it never inserts hard paragraph separators or silently joins paragraphs. Use the ordinary document editing commands for hard paragraph changes.

A literal occurrence can split a Unicode grapheme (for example a base letter without its attached mark, one component of a joined emoji, or half a surrogate pair). Such an occurrence is counted and highlighted, with an explicit warning, but it is **highlight-only**: document selection is not expanded to it, and Replace is disabled for that occurrence. Replace All is disabled if any occurrence splits a grapheme; it never silently skips or expands those ranges. Navigate to a safe occurrence for a single replacement, or search for the whole cluster.

**Replace** changes the current safe match; **Replace All** applies all non-overlapping matches from one current committed basis in one atomic Undo step. Inserted replacement text is not searched again during that same operation. Empty search disables replacement; an empty replacement deletes. New text inherits the first matched logical text unit's formatting, as with ordinary selected-text replacement. Unaffected text/styles/hard separators keep their identities. If deletion empties a paragraph, the established ordinary deletion rule retains the affected text's typing style for that empty paragraph. Bulk expansion beyond the existing 100,000 UTF-16-unit prototype file limit is refused before changing anything. Identical text with identical formatting is a no-op.

Document changes recompute results; commands refuse a stale captured basis, including edit-then-Undo and foreign-owner bases. During active document composition, pending settlement or degraded input admission, search navigation/replacement is paused. No candidate is rewritten or replayed and no delayed replacement is queued; explicitly retry after composition/recovery finishes. Search-field typing and Ctrl+Z/Ctrl+Y use field-local history. To Undo/Redo document replacements, press Escape and Ctrl+Z/Ctrl+Y, or use the existing document toolbar. Completed replacement transactions participate in the same automatic committed-content recovery copies as ordinary edits.

Try this on the disposable multi-page sample: Ctrl+F, search `کتاب`, Enter, Shift+Enter, then Shift+Enter again to wrap to the last match on a later page. Ctrl+H, enter `قلم` in With, Replace once and then Replace All. Escape, Undo, Redo, Save As to a disposable file, close and reopen. The sample file itself is not overwritten. Run `python desktop-prototype/verify.py --find-replace-milestone` for the bounded current writing/search/recovery/Urdu integration suite.

## Persistent paragraph direction and alignment

The **Direction** and **Align** controls sit beside the typeface selector. Direction is **Auto**, **RTL** or **LTR**. Alignment is **Start**, **Center** or **End**. Start/End are relative: RTL Start is the right edge and RTL End is the left; LTR uses the opposite edges. Center is physical center. There is no justification, kashida insertion, character spacing or injected bidi-control text. Commands preserve stored character order, inline formatting and the logical selection.

Targeting is defined in reusable document/command code, not the toolbar. A collapsed caret affects its paragraph, including empty/trailing-empty paragraphs. A nonempty selection uses its half-open logical range: ending exactly at the following paragraph's start excludes that paragraph. Backward selections have the same targets. A selected hard separator belongs to its preceding paragraph. For `abc\nxyz`, `[0,4)` targets the first paragraph only; `[0,5)` targets both. Mixed stored values display **Mixed**; mixed resolved physical edges do not count as mixed when the stored value is the same Auto or Start.

Auto keeps the established isolate-aware first-strong behavior: strong characters inside isolates do not choose the outer paragraph base; neutral/numbers-only and empty paragraphs inherit the preceding resolved direction, with LTR at the root when no strong text exists. Explicit RTL/LTR overrides that base without changing the text. Keyboard visual navigation, carets, selections, hit testing, accessible bounds and candidate-position queries use the resulting layout in continuous and paged views.

**Inheritance:** Enter/split copies the source paragraph's stored direction/alignment to new paragraphs (Auto remains Auto rather than freezing its current resolution). Soft breaks create no new paragraph. Joining keeps the left paragraph's stored properties. Replacement/deletion keeps surviving root/separator anchors and their properties; deleting a separator removes its following paragraph anchor and merges into the left. Auto re-resolves from the surviving text. Empty-paragraph inline typing-style retention remains the existing rule. Undo/Redo restores paragraph metadata with the exact text/inline state. One actual property change is one document Undo transaction; an unchanged value is a no-op.

During composition, these commands use the existing settlement queue with captured paragraph anchors. They do not rewrite candidates; surviving targets receive the property change after settlement, removed targets refuse, and the existing timeout/cancellation behavior applies. Input-paused/recovery-degraded controls stay disabled. Native IME popup movement and real screen-reader behavior remain unqualified; automated candidate-coordinate/AT API checks are distinct evidence.

**Persistence compatibility:** new saves/exports/checkpoints use private prototype `.astra` **version 4**, not a production schema freeze. It adds one root paragraph-property byte after the starting inline-style byte and one following-paragraph byte per UTF-16 unit (nonzero only on hard separators). Packed bits are direction Auto=0/RTL=1/LTR=2 plus four times alignment Start=0/Center=1/End=2; invalid values and paragraph properties on text units are rejected. Existing SHA-256, raw UTF-16 and structural tags remain. Versions 1–3 load as Auto/Start and retain their existing inline/typing-style defaults. Saving an old file writes v4; older prototype binaries cannot read it. The repository's original v3 sample remains unchanged and readable.

Save/Open, automatic committed-content recovery, retained-draft export/application and Find/Replace preserve the properties. Retained recovery still requires its owned exact basis; a property change invalidates an old draft basis even when the text is unchanged. Automatic recovery still protects only its last completed committed checkpoint, not provisional/capsule/quarantine input or power-loss durability.

Launch `write-urdu.cmd --sample`. Use Ctrl+Home and set RTL/Start. Find `Disposable`, Escape, set LTR/Start on that English paragraph. Find `حصہ 1`, Escape, Center it. Find `صبح`, Escape, set End on the Urdu body paragraph (its Auto resolves RTL, so End is left). Try arrows/Shift+arrows and typing; Undo/Redo; switch continuous/pages, then Save As, close and reopen. Verify with `python desktop-prototype/verify.py --paragraph-milestone`.
