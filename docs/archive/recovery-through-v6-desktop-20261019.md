# Prototype retained-draft recovery

Input-host recovery keeps attributed desired documents and their captured committed basis in memory. It is separate from disk autosave/crash recovery. The open C0/S0/native gates and production recovery-artifact policy remain unchanged.

Each distinct recovery is an ordered session record with a runtime logical key. Metadata copies update that record; equal text in separate events does not deduplicate records. A replacement host shares the session and merges any records supplied by its replacement factory. No record is silently dropped because another composition recovered. The active selection is independent of the stored collection.

The recovery row lets you choose a record, inspect its complete desired text, export its full document, apply it or discard just that record. It lives below the normal toolbar so recovery actions fit the prototype's minimum width. Applying requires the originating runtime owner, exact committed root, committed-basis revision and identity generation. Failed or unchanged application retains the record. A confirmed apply removes only the captured stored version, protecting newer/reentrant work. Explicit session discard resolves all retained draft records and quarantined callbacks.

Recovery's basis revision advances when the final committed `Dc` changes, including raw attributes or identities. The visible document revision still tracks provisional display changes. Canceled candidates and caret moves therefore do not stale an untouched committed basis, and no capsule is retagged after abort. Accepted edit/Undo, attribute-only edit/Undo and identity-only move/inverse still invalidate old bases even if the old value returns. This follows the current plan's `recoverDraft(..., expectedBase)` check against `Dc`; it does not change semantic revision policy or choose a persistent document-ID representation.

Closing a clean document still asks when retained drafts exist. Cancel or Keep Editing preserves them. Saving accepted content cannot automatically close over pending drafts. Discard All and Close is explicit and clears the session's recovery work after any active composition is aborted. Applying/exporting a draft is never inferred from a normal document save.

**Export Draft** creates a separate prototype `.astra` document using the versioned prototype codec (new exports v4; v1–v3 still readable). It preserves current supported raw UTF-16, B/I, start/paragraph typing styles, paragraph direction/alignment and hard-versus-soft breaks, including empty desired documents. It does not apply or discard the capsule, change the main save point/path or persist owner/basis tokens. Opening that file creates a new document through the existing loader; durable canonical ID retention remains S0 work. The current document's path is refused as an export destination. Failed IO preserves records and existing files. The older `exportRetainedDraft` method remains a plain composing-fragment diagnostic, not this rich export.

`--recovery-ui-check --host-result=<new-output-path>` runs actual offscreen shell checks with synthetic input and supplied file destinations, without desktop control or OS file-dialog interaction. Nine groups cover repeated recovery, Cancel, save-close, copy/merge semantics, the actual Export Draft button, failed IO, layouts at 940×400 / 940×700 / 1020×700, selection/stale apply/reentrant work, and explicit discard-all close. Rendered PNGs are retained; they are own-app renders, not desktop screenshots. Kernel recovery and mounted lifecycle suites also run in `python desktop-prototype/verify.py`.

These checks do not qualify OS IME retirement, native focus/restart fences, clipboard interoperability, general memory/capacity budgets, durable recovery or production autosave. Large-draft referenced artifacts and production retention limits remain planned; this prototype conservatively retains records instead of silently evicting work. A new owner/pairing or a user-visible text match is not permission to bypass native lifecycle qualification.

## Unverified input disposition

Callbacks arriving while input admission is paused remain separate from accepted document content. A clean document still asks before closing if these callbacks remain. Keep Editing, Cancel and saving accepted content preserve them; save-close cannot bypass them. The close prompt identifies draft/callback counts and the loss from Discard All and Close.

Inspect Input shows readonly text plus numeric UTF-16 and callback metadata. Export Input creates a separate new diagnostic JSON file (choose an unused filename); it records raw units, escaped text, committed-character count, caret, epoch and timestamp. It is not a replayable document/recovery format, never applies content and does not clear entries or change the main save point. Existing files/main document are not replaced. Failed IO keeps the queue. Discard Input confirms a snapshot; newer arrivals, even value-equal callbacks, remain. No native provenance or completion fence is implied.

## Automatic committed-content copies

The writing shell now checkpoints committed roots into a separate application-owned directory. See [WRITING.md](writing-through-v6-desktop-20261019.md#automatic-local-crash-recovery) for scheduling, fallback, restore/discard and loss-window details. The capsule/quarantine features in this document remain separate and memory-only; a crash can lose them. They are not serialized into accepted documents or replayed by automatic restore. Normal Save still writes only on explicit request.
